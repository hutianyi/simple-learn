# 简单读阅读包 v1

此约定由 App 实际读取器实现，是未来新 Skill 的输出依据。旧 `ket-nonfiction-reader` 保持原样。制作流程必须先交付 Markdown 给用户审阅，确认后再配图与打包；脚本本身不代替人工确认或内容核验。

## 文件与身份

`.simpledu` 是一个 ZIP 文件，支持 Store / Deflate，不支持加密、分卷、ZIP64、符号链接或目录条目。只打包文件，使用 UTF-8 相对路径；不得包含绝对路径、反斜线、冒号、空路径段、`.`、`..` 或重复文件名。

```text
manifest.json
content.json
images/photo1.jpg
images/photo2.jpg
parent/reading.md       # 可选，审阅后的家长完整材料
parent/words.txt        # 可选，教材词表
```

每包不超过 64 MiB，解压后合计不超过 96 MiB，最多 256 个文件，每文件不超过 16 MiB。`manifest.json` 不超过 128 KiB，`content.json` 不超过 2 MiB。单图只接受 JPEG / PNG，最大 8192 × 8192 且不超过 2400 万像素，必须可实际解码。

`manifest.json`：

```json
{
  "format": "SimpleDu",
  "schemaVersion": 1,
  "batchID": "ket-20261116-01",
  "revision": 1,
  "title": "KET 阅读 · 2026-11-16",
  "files": {
    "content.json": "该文件原始字节的 SHA-256 小写十六进制",
    "images/photo1.jpg": "该图片原始字节的 SHA-256 小写十六进制"
  }
}
```

`files` 必须列全除 manifest 自身外的所有文件，包括可选家长资料。App 同时验证 ZIP CRC 与文件 SHA-256。上例校验值只是说明，不能直接使用。

批次、文章、阅读单元、段落、题目的编号均为 1～100 个 ASCII 字母、数字、`-` 或 `_`；各相应范围内唯一。正文段落编号需在同篇全部单元中唯一。

- 同一内容使用稳定 `batchID`，修改内容递增 `revision`，不要为重复导入随机换编号。
- 版本为 1～1000000 的整数；标题最长 180 个 UTF-16 单元。
- 同包多篇按数组原顺序进入书架，一篇一卡片；新批次在前。
- 重复包跳过；同批次较高版本可经预览确认后导入，旧版完整内容和成绩保留在本地及备份中，书架展示最新版本。旧成绩不套用到新题目；当前界面只展示当前版本的练习历史。
- 同批次同版本但内容不同为冲突；较旧版本不覆盖当前版本。文件名和 Day 不用于判断身份。

## 文章、图文与题目

`content.json` 的基本结构如下。这里仅展示一题以说明字段；新 Skill 的每篇五题要求在内容生产时核验，App 支持历史材料的不同题数。

```json
{
  "articles": [
    {
      "id": "farm-to-plate",
      "dayNumber": 1,
      "articleNumber": 1,
      "title": "From the Farm to Your Plate",
      "cover": "images/photo1.jpg",
      "units": [
        {
          "id": "where-food-begins",
          "heading": "Where Our Food Begins",
          "image": "images/photo1.jpg",
          "paragraphs": [
            {
              "id": "p1",
              "runs": [
                {"text": "Farmers grow ", "target": false},
                {"text": "wheat", "target": true},
                {"text": ". People use it to make flour.", "target": false}
              ]
            }
          ]
        }
      ],
      "questions": [
        {
          "id": "q1",
          "prompt": "What do people make from wheat?",
          "options": ["Flour", "Water", "Ice", "Meat"],
          "answer": 0,
          "explanation": "The article says people use wheat to make flour.",
          "evidence": ["p1"]
        }
      ],
      "sources": [
        {"title": "核验过的实际资料标题", "url": "https://example.org/verified-source"}
      ]
    }
  ],
  "images": [
    {
      "path": "images/photo1.jpg",
      "alt": "Wheat grains and flour",
      "credit": "实际来源、作者、许可或原创生成说明，以及所需署名"
    }
  ]
}
```

除可选的 `dayNumber` / `articleNumber` 外，全部字段均应提供。编号字段为 1～1000000 的整数，仅用于书架封面的 Day / Article 标签；同一天单篇显示“Day N / Article”，多篇显示原 Article 编号。旧整包可从 `dayNN-articleN` 文章编号读取 Day 和篇号，旧 Day 14 试用包兼容 `ket-day14` 批次号，无需重导；无法确认 Day 的材料显示 Reading，不猜测日期。缺编号时不会修改文章原有身份或进度。

无来源可用空 `sources`，无解释可用空字符串，无依据可用空 `evidence`。这些空值只用于兼容历史材料，不豁免新 Skill 的事实核验和出题标准。

- 正文是纯文本 runs，不解析 HTML、脚本或远程图片。保留每个空格和标点；连续 runs 拼接必须等于已审阅的原文。
- `target` 只标记经语境核对符合教材词性、词义的具体出现，不由 App 全局匹配字符串。文章生产规则决定哪些出现应突出。
- 一个 unit 表示自然知识点与其配图关系，不是硬编码的一屏。App 按屏幕空间和字号继续分页，原文不重写；阅读进度按单元、段落和 UTF-16 字符位置保存。
- 图片不包含标题、正文或整道选择题；必要的知识图示标签可保留在图内。`alt` 说明图片内容，`credit` 提供真正的来源与许可；不能将普通生成场景冒充特定事件实拍。
- 允许一包 1～30 篇，每篇 1～80 个单元、最多 400 个段落、最多 60000 个 UTF-16 正文单元。每段 1～200 个 runs，合计最多 10000 个 UTF-16 单元。
- 每篇 1～60 道题，恰好四个不同的非空选项。`answer` 是 **0 起始**的选项下标：A=0，B=1，C=2，D=3；不可写字母。
- 题干、选项最多 1000 个 UTF-16 单元，解释最多 2000 个；`evidence` 引用本篇真实段落编号。
- 正确答案、解释只在提交后显示。用户选中选项可改选；提交后该题锁定，重练另开一轮，首次作答保留。
- `sources` 的 URL 必须是有效 HTTP / HTTPS 链接，显示在家长资料，不混入儿童正文。

## 制作命令

在简单学项目目录执行。命令只读取已确认内容和本地插图，新建一个包；拒绝覆盖既有输出。

```sh
python3 Scripts/make-du-package.py \
  --content "/绝对路径/本批/content.json" \
  --assets "/绝对路径/本批" \
  --batch-id "ket-20261116-01" \
  --revision 1 \
  --title "KET 阅读 · 2026-11-16" \
  --markdown "/绝对路径/已确认阅读材料.md" \
  --output "/绝对路径/阅读包.simpledu"
```

图片路径相对于 `--assets`，例如 `/绝对路径/本批/images/photo1.jpg`。可加 `--words` 打包词表。制作脚本生成清单和校验值，App 导入时进一步完整核验语义结构和图片；制作成功不代替事实、词义、答案或视觉检查。

## 添加到简单听

书架或书柜长按文章可选择“添加到简单听”。从结构化正文生成该篇听力材料，仅含标题、正文及正文小标题；图片、题目、答案、来源和词表不加入。已知迁移格式 `pN-sM` 的连续跨页段落重新合并，连续重复的页内小标题只保留一次。

由 App 注入跨模块添加动作，简单读不直接访问简单听存储。简单听公开添加接口复用其 `LibraryStore.commit`、`ListenLibrary.importing` 和 `LibraryFile.save`，沿用导入顺序与安全副本。来源键为 `simpledu:` 加文章版本身份，同一版本重复点击会跳过；在简单听删除该篇后可重新加入。原有粘贴导入仍按原规则追加。

联动只新增听力文章，不自动打开或播放，不改变阅读与归档状态、既有听力文章和播放设置。两边数据独立，删除其中一边不连带删除另一边；各自继续进入首页整体备份。

从 2.9 起，正文到达最后一页会保存进度中的可选 `readingCompleted`。完成该篇全部选择题（已有完整 attempt）后自动询问是否添加到简单听，不判断正确率，也不等待点“查看结果”或完成重做。答题在前、阅读在后的情况，在阅读完成后同样可询问；手动标已读不代替这两个完成条件。既有材料可能有不同题数，均以实际全部题目为准，不硬编码五题。

选择“添加”复用原有长按导入与去重：已在简单听中则告知并跳过，添加后不播放。选择“暂不添加”不会导入。`libraryStates` 的可选 `listeningPromptHandled` 按文章内容版本持久保存选择；两种选择都只问一次，重做/重开/标为未读不清除它，备份恢复保留，删除文章清理，新版本独立。用户仍可随时长按手动添加；添加失败会明确提示，可通过长按重试。未处理的询问保留待询问状态，防止在退出或重做后丢失。

## 阅读标记与书柜

书架右上角“选择”进入多选，逐篇点选或全选当前所在位置的文章；底部可标为已读、未读，或手动收进书柜。已读文章自动归入书柜，无需“收起全部已读”按钮。默认进入书架，书柜中的文章保留内容、阅读和答题记录，标为未读可移回书架。

整理状态与作答记录分开：手动标为已读不生成成绩，标为未读也不清除首次回答、历次成绩或阅读位置，但会移回书架。标为未读后重新打开文章优先进入正文，完整重练结束后自动恢复已读并收进书柜；原有答题完成记录不会被伪造或删除。答题结果页提示文章已自动收进书柜，可返回书架或继续阅读/答题，不再提供保留在书架的操作。

索引中的可选 `libraryStates` 按内容版本和文章编号保存 `readOverride`（可选 Bool）与 `archived`（Bool）。没有显式标记时，从已有完整答题历史推断已读；展示位置由“已读或 archived=true”决定，因此旧版已读文章和恢复的已读文章也直接进入书柜，无需改写旧索引。新的已读操作同时保存归档状态；移回书架时清除归档并标为未读，避免被自动规则再次收起。新版本内容从未读、未收起开始，旧版本整理状态仍随历史备份保存。归档不改写阅读包格式，已发出的 `.simpledu` 不必重新制作或导入。

归档状态与阅读标记进入模块及首页整体备份；删除文章清除对应各内容版本的整理状态。书柜可批量移回书架，“标为未读”也会直接移回，保留现有学习记录。归档提供缩小淡出和网格补位动画，尊重系统减少动态效果。

## 删除文章

书架长按文章可选择“删除文章”，二次确认后从书架移除该卡片，并清除同批次同文章编号各内容版本的阅读位置、选中选项、首次回答和历次答题。其他文章及其他独立阅读包不受影响。

删除标记随备份保存，恢复删除后的备份不会重新显示已删文章。再次手动选择当前原阅读包，可在导入预览中确认重新加入已删文章；重新加入从空白进度开始，其余文章的进度保留。新版本不会在普通更新中自动复活已删文章。

为了保留同包其他文章，原始共享阅读包作为材料来源继续保存；删除动作不改写外部原件或之前导出的旧备份。索引新增可选 `deletedArticles` 字段，旧版没有此字段时按未删除处理。

## 本地数据与备份

阅读包原件作为不可变文件保存在模块 Packages 目录；Index.json 保存安装记录、字号、阅读位置、选中但未提交的选项、首次回答和历次练习结果。进度保存不重写图片。

首页全局备份包含简单读所有已安装版本的原始阅读包与索引，可以在来源 iCloud 文件已经移动或删除后独立恢复。简单读界面隐藏独立备份与恢复入口，底层完整 JSON 备份能力保留用于全局备份。恢复先完整校验，写入不可变包，再原子替换索引；替换前保留原索引安全副本，既有包不删除。

恢复不含 SimpleDu 的旧整体备份时，只恢复其原有模块，保留当前简单读。升级前未完成的整体恢复日志也按这一原则回退。恢复前安全副本不等于外部备份。

## 验证及设备验收

```sh
python3 Scripts/run-du-validation.py
```

核心测试可以在 Mac 运行，覆盖 ZIP 安全边界、格式与校验值、实际图片解码、多篇拆分、重复和更新、未提交状态、首次回答、重练、持久化、完整备份、旧整体备份与中断恢复，以及跨字号和 Unicode 的分页文本完整性。分页测试使用同一套分页代码，Mac 使用 AppKit 字体测量；不能替代 iPad 的 UIKit 实际版面。

设备上仍需验证：iCloud 冷下载和取消、多包导入、横竖屏和大字号、左右滑动、误触改选、作答中退出恢复、重练与首次成绩、完整备份导出恢复。当前开发机没有可运行的 iPad 模拟器；不把无签名编译或 Mac 核心测试当成设备验收。
